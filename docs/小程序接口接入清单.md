# 会务通知小程序接口接入清单

核对日期：2026-10-10。目标服务器：http://36.139.203.131:8888。

本清单替代此前基于 36.140.102.253 的核对结果。依据本项目 18 个页面业务脚本、模板、全局配置与请求模块。开发者工具此前确认打开本项目并停留登录页。

## 核验边界

- utils/config.js 与本次指定地址一致；代码路径不带 /dev-api，不应根据另一个服务器的文档统一添加前缀。
- 目标服务器 /swagger-ui/index.html 返回 HTTP 200；/swagger-resources 返回 []；/v2/api-docs、/v3/api-docs 返回 HTTP 404，当前无法读取接口定义。
- GET /appLogin 返回 HTTP 200、业务 code=405。GET 用户信息、当前会议、appInfoList、本人状态、本人座位、座位图、本人填报路径返回 HTTP 200、业务 code=401。这只能说明未登录访问被处理，不能证明具体控制器存在或业务成功。座位等带会议 ID 的只读探测使用 0，未读取真实个人记录。
- 没有进行登录、提交或服务端数据修改。所有“已调用”均指代码存在调用，尚未完成登录后的联调。

## 1. 代码已调用：14 项，应逐项联调

所有路径均相对于上述目标服务器。

| 功能 | 方法 | 路径 | 对应页面及参数 |
|---|---|---|---|
| 登录 | POST | /appLogin | login；JSON username/password，期望顶层 token |
| 当前用户 | GET | /meeting/user/getInfo | 登录后、启动恢复、个人中心；期望 user/personId |
| 当前会议 | GET | /meeting/main/appCurrentMeeting | 首页、材料、座位、请假；期望 data.id/meetingName/startTime/endTime/meetingLocation |
| 会议信息列表 | GET | /meeting/main/appInfoList | 首页、日程；首页本地筛选今天，日程按开始日期分组 |
| 会议详情 | GET | /meeting/main/appInfo/{meetingId} | meeting-detail；期望 data.meeting/persons/tabs/topicCount/fileCount |
| 会议日程 | GET | /meeting/daily/list | materials；query meetingId，期望 data 数组含 dayStr/dayType/title/contents |
| 全分类材料树 | GET | /meeting/main/categories/{meetingId}/files | materials；categoryId/categoryName/topics/files |
| 文件下载/预览 | GET | /downloadServlet/download | query fileId/categoryId/meetingId；下载文件流，再用 wx.openDocument 打开 |
| 请假提交 | POST | /meeting/person/appLeave/{meetingId} | leave；当前没有传请求体，填写的原因没有提交 |
| 本人参会状态 | GET | /meeting/person/appMyStatus/{meetingId} | leave；期望 status/roleType |
| 本人座位 | GET | /meeting/person/appMySeat/{meetingId} | seat；期望 seatNo/tableCard/groupName |
| 座位图 | GET | /meeting/person/appSeatMap/{meetingId} | seat；期望 layoutName、seats，格子含 id/r/c/no/name/mine/disabled/aisle/blank |
| 本人填报信息 | GET | /meeting/personInfo/appMyInfo/{meetingId} | info-form、info-record；期望 submitted、填报字段、submitTime |
| 提交填报 | POST | /meeting/personInfo/appSubmit/{meetingId} | info-form；JSON phone/hotelNeed/dietType/transport/arriveDate/leaveDate/remark |

填报客户端枚举：hotelNeed=0/1；dietType=none/veg/halal/other；transport=self/bus/rail/air/other；日期 yyyy-MM-dd。

状态客户端映射：0=请假、1=到会、2=缺席、3=未设置。这些字段和枚举均来自客户端代码，需要实际后端响应确认。

请求封装当前发送 Authorization: Bearer <token>，按业务 code===200 判断成功，通常取 body.data；下载使用带鉴权的 arraybuffer 请求并识别 JSON 错误体。

## 5. 关键缺口及验收顺序

1. 先用普通参会账号确认登录、token、会议列表与详情，再核对材料权限及下载。
2. 通知详情“出席/请假”目前只调用 setData 和 Toast，必须接入后端回执并能再次查询。
3. 请假页必须把原因持久化；当前重新进入时根据 status 拼装记录，日期使用当天，原因/审批人显示占位符，不能当作历史证据。
4. 个人中心“我的回执记录”现在指向 info-record，只展示当前会议的参会信息填报，应明确菜单名称或增加通知回执历史。
5. 提交信息/回执/请假后，重新打开页面和重启小程序仍能读取真实记录；切换会议按 meetingId 查询，退出清理会议缓存，避免跨账号复用旧数据。
6. 最后接入住宿、用餐、班车、联系信息、偏好与代表字段。正式发布前确认 HTTPS 合法域名。
